TASK 1 — FIX LOGIN REDIRECT LOOP
============================================================

Symptom:
  - User logs in, lands on /dashboard (works)
  - Clicking sidebar links OR hard-refreshing /dashboard/progress,
    /dashboard/analytics, /dashboard/explore etc. redirects to /login

Root cause:
  Lovable's preview-auth-storage shim is still wired into the
  Supabase client. It delays session reads by ~2 seconds via a
  postMessage timeout, during which `user` is null and
  ProtectedRoute fires a redirect to /login.

Fix — in this exact order:

  1. Delete src/integrations/lovable/  (whole folder)
  2. Delete src/integrations/supabase/previewAuthStorage.ts
  3. Rewrite src/integrations/supabase/client.ts:
       - import { createClient } from '@supabase/supabase-js'
       - read VITE_SUPABASE_URL, VITE_SUPABASE_PUBLISHABLE_KEY
       - throw at module load if either is missing
       - include createSupabaseFetch helper that strips a Bearer
         Authorization header when the key starts with
         'sb_publishable_' or 'sb_secret_'
       - auth: { persistSession: true, autoRefreshToken: true }
       - export const supabase (named export)
       - NO reference to brokeredPreviewStorage
  4. Rewrite src/lib/auth-context.tsx:
       - remove Lovable import
       - signInWithGoogle → supabase.auth.signInWithOAuth
       - keep the same public API and signatures
       - export AuthUser type
  5. npm uninstall @lovable.dev/cloud-auth-js
  6. Verify: grep -rin "lovable" src package.json vite.config.ts index.html
     Must return ZERO matches in src/ and package.json.
